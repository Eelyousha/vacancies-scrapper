# Vacancies scrapper

Локальное Go-приложение собирает вакансии с сайтов работодателей, хранит их в
SQLite, отслеживает изменения и безопасно архивирует исчезнувшие объявления.
Работает локально: Go-сервер отдаёт HTML-интерфейс и JSON API, статические
ресурсы встроены в бинарник, CDN и Node.js не требуются.

## Возможности

* YAML-конфигурация источника со строгой проверкой полей и CSS-селекторов до
  запуска браузера;
* browser dry run с превью до пяти вакансий и одноразовым `test_token`;
* Chromium-сбор с пагинацией, detail pages и пользовательской поисковой фразой;
* идентификация вакансий по нормализованному URL или fallback-фингерпринту,
  история `title`, `company` и `salary`, безопасная архивация;
* локальный dashboard: лента с фильтрами, сводка запусков, конструктор и
  список источников, ручной запуск из браузера;
* диагностический CLI, JSON API и SQLite-миграции.

## Быстрый старт

Требуется Google Chrome или Chromium в `PATH`.

```sh
go run ./cmd/vacancy-server -database vacancies.db
```

Сервер слушает `http://127.0.0.1:8080`; адрес меняется флагом `-address`.
Ручной запуск защищён независимым лимитом `-run-timeout` (по умолчанию `30m`):
для особенно долгого источника, например, передайте `-run-timeout 45m`.
Журнал сервера выводится в консоль; чтобы одновременно дописывать его в файл,
передайте, например, `-log-file vacancy-server.log`.
Откройте `http://127.0.0.1:8080`. Основной browser-сценарий:

1. Перейдите в «Новый источник», вставьте YAML, укажите slug и выполните dry run.
2. Проверьте превью и сохраните источник выданным одноразовым token.
3. В списке источников введите при необходимости поисковую фразу и нажмите
   «Запустить».
4. Dashboard покажет вакансии и итог запуска.

Контракт всех маршрутов описан в [_docs/04-api-ui.md](_docs/04-api-ui.md).
Пример YAML — в [_docs/examples/source.example.yaml](_docs/examples/source.example.yaml).

## YAML-конфигурация

Шаблон — в [_docs/examples/source.example.yaml](_docs/examples/source.example.yaml).
Обязательны название сайта, абсолютный URL, параметры страницы и селекторы
контейнера, карточки, названия и ссылки. `search_url_template` подставляет
`{query}` с URL-кодированием; если его нет, `search_on_ui` вводит фразу в
страницу и отправляет её click или Enter.

## Диагностический CLI

`vacancy-scraper` не сохраняет данные: он нужен для проверки селекторов и
печатает результат в JSON.

```sh
go run ./cmd/vacancy-scraper -config yandex_vacancies.yaml -search "Go developer" -max-results 10
```

Для визуальной отладки добавьте `-headless=false`. Общий лимит задаёт
`-run-timeout`; для короткой проверки доступны `-max-pagination-iterations` и
`-max-detail-pages`.

### Короткая проверка источника

Перед полным ручным запуском сначала проверьте сайт с небольшими лимитами:

```sh
go run ./cmd/vacancy-scraper -config yandex_vacancies.yaml \
  -max-pagination-iterations 3 -max-detail-pages 5 -run-timeout 2m
```

Эта команда ничего не сохраняет в SQLite: она печатает результат в JSON. У
`vacancy-server` таких флагов нет, потому что его источники хранят YAML в БД.
Для короткой проверки через браузерный интерфейс создайте отдельный источник с
новым `slug`, задайте в `pagination` небольшие `max_iterations` (например, `3`)
и `max_attempts_without_new_data` (например, `2`). Чтобы не ждать
последовательного обхода всех карточек, временно не добавляйте в этот тестовый
YAML блок `detail_page`. После dry run сохраните источник и запустите его.

## Ограничения и далее

Уже доступны базовый HTML-интерфейс и ручные запуски. Ещё не готовы отметки
«просмотрено»/«скрыто» из ленты, история изменений в интерфейсе, редактирование
и import/export источников, а также cron/interval и фоновые запуски.

