# Поисковая фраза пользователя при ручном запуске

**Дата:** 2026-09-12
**Статус:** выполнено
**Этап ТЗ:** [этап 2](../05-implementation-plan.md)

## Проблема и цель

`search_url_template` и `search_on_ui` описаны в YAML, но scraper их не
исполняет. Пользователь выбрал ввод поисковой фразы при ручном запуске.

Цель — передавать фразу из HTML-формы и CLI в scraper: подставлять
URL-encoded значение вместо `{query}` в URL-шаблон либо вводить его в UI.

## Границы

Входит: `-search` в CLI; поле поиска в форме запуска источника; URL-search с
`{query}`; UI-search с вводом и click/Enter; unit-тесты преобразования URL и
изолированные тесты передачи фразы.

Не входит: сохранение поисковой фразы в YAML/БД, поиск без фразы, изменения
JSON API и фоновые расписания.

## План и решение

Ввод пользователя передаётся отдельным параметром, не изменяя сохранённый
YAML. При наличии `search_url_template` он имеет приоритет; иначе применяется
`search_on_ui`. Фраза URL-encoded. Пустая фраза сохраняет текущий запуск без
поиска.

## Проверка и результат

Результат: `{query}` заменяется во всех вхождениях URL-encoded значением;
форма запуска передаёт `search_query`; пустая фраза использует прежний путь;
browser без query-поддержки отклоняет непустую фразу. У UI-поиска фраза
вводится и отправляется click либо Enter. Выполнены успешно: `go test ./...`,
`go vet ./...`, `go build ./...`, `git diff --check`.
