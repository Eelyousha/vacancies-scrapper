# Независимый контекст и timeout ручного запуска

**Дата:** 2026-09-12
**Статус:** выполнено
**Этап ТЗ:** [этапы 2 и 5](../05-implementation-plan.md)

## Проблема и цель

Полный ручной запуск из HTML использует `r.Context()`. Долгая пагинация или
detail pages могут пережить HTTP-навигацию, после чего scraper получает
`context canceled`, хотя конфиг и Chromium исправны.

Цель — выполнить ручной run в независимом server-side контексте с явным
ограничением времени и сохранить диагностику terminal failure.

## Границы

Входит: независимый контекст для HTML и JSON ручных запусков; флаг сервера
`-run-timeout` с безопасным значением по умолчанию; `504` на timeout; тесты
отменённого HTTP-контекста и deadline. Не входит: фоновые jobs, очередь,
отмена из UI и расписания.

## План и решение

Чтение и фиксация состояния запуска используют независимый контекст хранилища.
Перед обращением к браузеру lifecycle создаёт
`context.WithTimeout(context.Background(), timeout)` и передаёт его scraper.
При deadline run и источник переводятся в `failed`, а API отвечает `504`.
Default — 30 минут; флаг `-run-timeout` позволяет изменить лимит. Временная
отмена HTTP-контекста больше не останавливает сбор.

## Проверка и результат

До реализации добавлены два изолированных теста. Фактический результат:

* отменённый контекст HTTP-запроса не передаётся в scraper; запуск сохраняется
  как успешный;
* истёкший server-side deadline возвращает `504`, а run и источник получают
  статус `failed` с текстом `context deadline exceeded`.

Проверки: `go test ./...`, `go vet ./...`, `go build ./...`,
`git diff --check`.

## Сверка с ТЗ и следующий шаг

Соответствует критерию этапа 2: сохранённый источник не прерывается из-за
навигации браузера или закрытия соединения. Это также развивает задел этапа 5,
но не реализует фоновые jobs. Связанная карточка [№ 24](../backlog.md)
выполнена. Далее — интерактивная лента этапа 4.
