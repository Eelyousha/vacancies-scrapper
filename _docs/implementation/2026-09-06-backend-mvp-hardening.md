# Завершение backend MVP

**Дата:** 2026-09-06
**Статус:** выполнено
**Этап ТЗ:** [этапы 4 и 5](../05-implementation-plan.md)

## Проблема и цель

Read API уже реализован, но HTTP-контракт покрыт не полностью, ручной запуск
проверяется на занятость вне транзакции, а PATCH не управляет расписанием.

Цель — сделать backend пригодным для UI и безопасного ручного использования.

## Границы

Входит: HTTP-тесты read API, атомарная блокировка запуска, PATCH расписания,
явный неперсистентный import/export контракт.

Не входит: исполнение расписаний и HTML-интерфейс.

## План и решение

Запуск переводится на атомарный метод хранилища, который возвращает
`ErrInvalidTransition` при уже running источнике. PATCH принимает поля
`schedule_type`, `schedule_value`, `schedule_timezone`; репозиторий валидирует
их до записи. Import возвращает `{yaml, requires_dry_run:true}`.

## Проверка и результат

Проверены HTTP read/write API, конфликт concurrent run, валидное и невалидное
interval-расписание, import без записи в БД. Все сценарии пройдены.

Выполнены `go test ./...`, `go vet ./...`, `go build ./...` и `git diff
--check` — успешно.

## Сверка с ТЗ и следующий шаг

Завершает backend MVP и оставляет исполнение cron/interval этапу 5.
