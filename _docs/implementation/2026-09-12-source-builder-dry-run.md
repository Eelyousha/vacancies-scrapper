# Ядро конструктора источника: dry run и сохранение YAML

**Дата:** 2026-09-12
**Статус:** выполнено
**Этап ТЗ:** [этап 4](../05-implementation-plan.md)

## Проблема и цель

Dashboard позволяет читать уже сохранённые данные, но для добавления источника
пользователь всё ещё должен вручную вызвать JSON API. Это нарушает сценарий
«dry run → сохранение → запуск» в локальном браузере.

Цель — добавить серверный HTML-конструктор, в котором пользователь вставляет
YAML, получает dry run с превью и сохраняет источник только с выданным
одноразовым `test_token`.

## Границы

Входит:

* `GET /sources` с формой YAML, slug и именем источника;
* `POST /sources/test` для browser dry run и HTML-превью не более пяти вакансий;
* `POST /sources` для сохранения формы с проверкой одноразового token;
* сообщения в HTML о валидации, dry run и ошибках сохранения;
* ссылка на конструктор из dashboard и тесты полного HTTP form-сценария.

Не входит:

* редактирование существующего источника, import/export и расписания;
* запуск источника из HTML, HTMX и JavaScript;
* изменение JSON API, TTL/семантики token или YAML-контракта;
* изменения Chromium-сборщика и БД-схемы.

## План и решение

HTML-маршруты используют те же `dryrun.Service`, `config.Parse` и storage,
что JSON API; token остаётся привязанным к точным байтам YAML и `base_url`.
После успешного dry run сервер возвращает ту же форму с hidden `test_token`,
сроком действия и списком превью. Сохранение повторно проверяет YAML и
потребляет token; успех перенаправляет на dashboard.

Шаблон встроен через `embed.FS`, CSS использует существующий локальный
stylesheet. Ошибки формы возвращаются с HTTP 422 и сохраняют введённый YAML.

## Проверка и результат

До реализации должны быть добавлены тесты:

1. `GET /sources` возвращает HTML-форму и ссылку на локальный stylesheet;
2. valid YAML через `POST /sources/test` показывает превью и hidden token;
3. `POST /sources` с подходящим token создаёт источник и перенаправляет на
   dashboard; без token либо с изменённым YAML возвращает 422 и не пишет в БД;
4. ошибочный YAML остаётся в форме вместе с понятной ошибкой.

Результат:

1. `GET /sources` отдаёт HTML-форму с локальным stylesheet; пройдено.
2. Корректный YAML в `POST /sources/test` показывает превью и hidden token;
   пройдено.
3. Сохранение с подходящим token создаёт источник и отвечает `303` на `/`;
   отсутствие token или изменённый YAML отвечают `422` без записи в БД;
   пройдено.
4. Невалидный YAML остаётся в форме вместе с ошибкой `422`; пройдено.

Выполнены успешно: `go test ./...`, `go vet ./...`, `go build ./...` и
`git diff --check`.

## Сверка с ТЗ и следующий шаг

Инкремент реализует основной пользовательский путь конструктора источника из
этапа 4 и не расширяет backend-контракт. Следующий шаг — HTML-действия над
вакансиями либо отдельный инкремент редактирования/import/export источника.
