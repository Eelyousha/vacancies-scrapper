# Поддержка относительного пути SQLite

**Дата:** 2026-09-12
**Статус:** выполнено
**Этап ТЗ:** [этап 0](../05-implementation-plan.md)

## Проблема и цель

Стандартный запуск `-database vacancies.db` передаёт относительный путь. Текущая
сборка URI создаёт `file://vacancies.db`, где имя файла воспринимается как host,
а SQLite сообщает ложную ошибку `out of memory` при включении foreign keys.

Цель — корректно открывать относительные и абсолютные SQLite-пути.

## Границы

Входит: корректное формирование file URI, регрессионный тест относительного
пути, обновление записи и backlog. Не входит: миграции, схема, изменение
параметров CLI или восстановление повреждённых БД.

## План и решение

Использовать opaque-часть file URI, чтобы относительный путь формировал
`file:vacancies.db`, а абсолютный — валидный `file:/…`. Проверка foreign keys и
миграции остаются без изменений.

## Проверка и результат

Результат: регрессионный тест открывает БД по относительному пути, проверяет
миграции и foreign keys. Выполнены успешно: `go test ./...`, `go vet ./...`,
`go build ./...`, `git diff --check`.

## Сверка с ТЗ и следующий шаг

Уточняет критерий этапа 0 о запуске БД одной командой. Далее — интерактивная
лента этапа 4.
