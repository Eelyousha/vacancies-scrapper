# Предбраузерная валидация CSS-селекторов

**Дата:** 2026-09-12
**Статус:** выполнено
**Этап ТЗ:** [этап 1](../05-implementation-plan.md)

## Проблема и цель

YAML-парсер проверяет обязательность селекторов, но их синтаксическая ошибка
сейчас обнаруживается только после запуска Chromium. Это нарушает цель этапа 1:
объяснять неверный конфиг до браузера.

Цель — отклонять некорректный непустой CSS-селектор при `config.Parse` и
сообщать точное YAML-поле.

## Границы

Входит:

* синтаксическая проверка обязательных и непустых необязательных CSS-селекторов
  без браузера;
* контекстное сообщение об ошибке с путём YAML-поля;
* unit-тесты корректных и некорректных селекторов из list, pagination,
  detail_page и search_on_ui.

Не входит:

* проверка того, что селектор находит элемент в живом DOM;
* исполнение `search_on_ui` и `search_url_template`;
* изменение YAML-контракта или browser dry run.

## План и решение

Использовать уже доступный парсер CSS-селекторов `cascadia` внутри
`config.Validate`. Проверять только непустые значения, потому что часть полей
контракта необязательна. Ошибка оборачивается именем YAML-поля; это позволяет
исправить конфиг до создания Chromium.

## Проверка и результат

Результат: корректные селекторы проходят; некорректные list, pagination,
detail_page и search_on_ui селекторы отклоняются с путём YAML-поля. Выполнены
успешно: `go test ./...`, `go vet ./...`, `go build ./...` и `git diff --check`.
