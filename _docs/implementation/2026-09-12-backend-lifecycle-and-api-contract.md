# Надёжность lifecycle и JSON-контракт backend

**Дата:** 2026-09-12
**Статус:** выполнено
**Этап ТЗ:** [этапы 3 и 4](../05-implementation-plan.md)

## Проблема и цель

После аудита backend выявлены три нарушения наблюдаемого контракта: вновь
найденная архивная вакансия остаётся архивной, ошибка записи результата может
оставить источник в `running`, а API сериализует публичные поля в Go-форме
вместо принятого JSON snake_case.

Цель — сохранить корректное состояние вакансий и запусков при ошибках и
сделать JSON-ответы пригодными для будущего UI без привязки к именам Go-полей.

## Границы

Входит:

* реактивация архивной вакансии при следующем наблюдении того же identity key;
* перевод уже созданного запуска в `failed`, если не удалось сохранить его
  успешный результат;
* явные snake_case JSON-поля моделей, возвращаемых HTTP API, и тесты формы
  ответа.

Не входит:

* HTML/HTMX-интерфейс;
* cron/interval-исполнитель, лимиты браузеров и смена таймзоны;
* UI-поиск и изменение YAML-контракта;
* расширение состава историзируемых полей.

## План и решение

Добавлены изолированные тесты хранилища и HTTP API на каждый сценарий. При
обновлении существующей вакансии хранилище сбрасывает `listing_status` в
`active` и очищает `archived_at`, не меняя `user_status`. Такое возвращение
помечается в составе запуска как `updated`, поскольку изменилось состояние
листинга; история текстовых полей не создаётся, если они не менялись.

Обработчик ручного запуска вызывает `runlog.Fail` с независимым контекстом и
после ошибки `Finish`, поэтому ошибка сохранения результата завершает run и
освобождает источник для следующей попытки. Публичные модели storage получили
явные snake_case JSON-теги; API возвращает эффективные числовые `limit` и
`offset` после нормализации.

## Проверка и результат

До реализации должны быть добавлены тесты:

1. полный успешный запуск архивирует вакансию, следующее наблюдение той же
   вакансии возвращает её в `active`;
2. ошибка сохранения результата ручного запуска завершает run и источник
   статусом `failed`, после чего повторный запуск не блокируется;
3. ответы вакансий, источников и запусков используют snake_case и содержат
   эффективные значения пагинации.

Результат:

1. Вакансия архивируется при полном пустом запуске и при следующем наблюдении
   возвращается в `active` с очищенным `archived_at`; пройдено.
2. Искусственная ошибка вставки результата завершает run и источник статусом
   `failed`; повторный ручной запуск не получает `409`; пройдено.
3. Ответы вакансий, источников и запусков используют snake_case; ограничение
   `limit=500&offset=-5` возвращает эффективные `50` и `0`; пройдено.

`git diff --check`.
