# Dry run и API источников

**Дата:** 2026-09-05
**Статус:** выполнено
**Этап ТЗ:** [этапы 2 и 4](../05-implementation-plan.md)

## Проблема и цель

YAML сейчас сохраняется при CLI-запуске до проверки браузером. Это не позволяет
безопасно добавлять и менять источники в работающем приложении: невалидный
селектор или пустая выдача могут оказаться в БД.

Цель — реализовать сценарий ТЗ: HTTP dry run возвращает превью и временный
`test_token`; создание/обновление источника требует подходящий token; API может
вручную запустить сохранённый источник.

## Границы

Входит:

* разбор YAML из HTTP-тела и dry run с одной итерацией пагинации и 3–5 карточками;
* краткоживущий одноразовый token, связанный с хешем YAML и базовым URL;
* `POST /api/sources/test-config`, создание/обновление источника и ручной run;
* запрет пересекающихся запусков источника с `409 Conflict`;
* unit- и HTTP-тесты без запуска Chromium.

Не входит:

* HTML-интерфейс, импорт/экспорт, расписания и UI-поиск;
* изменение вакансий или API ленты;
* сохранение YAML через прежний прямой путь CLI без dry run.

## План и решение

API принимает JSON. `POST /api/sources/test-config` получает `{ "yaml": "…" }`;
успех возвращает `{ test_token, expires_at, preview }`. `POST /api/sources`
получает `slug`, необязательный `name`, `yaml`, `test_token` и настройки
источника. `PATCH /api/sources/:id` требует token только при передаче нового
YAML. `POST /api/sources/:id/run` синхронно выполняет сохранённый источник и
возвращает итог запуска.

Token живёт 15 минут и используется один раз. Dry run использует `base_url` из
YAML, ограничивает пагинацию одной итерацией, сохраняет не более пяти вакансий
в ответе и требует хотя бы одну с непустыми title и link.

## Проверка и результат

Проверены сценарии:

1. успешный dry run выдаёт preview и token — пройден;
2. пустой/некорректный результат не выдаёт token — пройден;
3. token нельзя применить к изменённому YAML или повторно — пройден;
4. создание источника принимает действительный token — пройден HTTP-тестом;
5. ручной запуск сохранённого источника сохраняет результат — пройден HTTP-тестом.

`cmd/vacancy-server` поднимает API на `127.0.0.1:8080` (настройка —
`-address`, `-database`). Прежний CLI теперь только диагностически извлекает и
печатает JSON; новые YAML и сохраняемые запуски проходят API-сценарий.

Выполнены `go test ./...`, `go vet ./...`, `go build ./...` и `git diff
--check` — успешно.
