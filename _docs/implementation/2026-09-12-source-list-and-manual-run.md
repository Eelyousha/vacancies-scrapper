# Список источников и ручной запуск из HTML

**Дата:** 2026-09-12
**Статус:** выполнено
**Этап ТЗ:** [этапы 2 и 4](../05-implementation-plan.md)

## Проблема и цель

HTML-конструктор уже создаёт источник после dry run, но пользователь не может
увидеть его состояние или запустить сбор без прямого обращения к JSON API.

Цель — завершить браузерный сценарий «создать источник → ручной запуск →
результат на dashboard» и сохранить те же ограничения пересекающихся запусков,
что у API.

## Границы

Входит:

* список сохранённых источников на `/sources` с текущим статусом, последним
  запуском и ошибкой;
* HTML-форма `POST /sources/:id/run` для ручного запуска;
* перенаправление успешного запуска на dashboard и отображение HTML-ошибки;
* `409 Conflict` при уже running источнике без создания второго run;
* HTTP-тесты списка, успешного запуска и конфликта.

Не входит:

* редактирование, удаление, import/export, расписания и переключение active;
* фоновый запуск: форма ожидает завершения уже существующего синхронного
  scraper-вызова;
* HTMX/JavaScript, изменение JSON API, YAML или БД-схемы.

## План и решение

Список источников добавлен к существующей странице `/sources`, где сохраняется
форма создания. Обработчик ручного запуска переиспользует общий внутренний
lifecycle, одинаковый для JSON и HTML: `StartExclusiveRun`, scraper,
`runlog.Finish` и `runlog.Fail`. Это исключает расхождение блокировки и статусов
между интерфейсами.

Успех отвечает `303` на `/?source_id=<id>`, чтобы пользователь сразу видел
результат этого источника. Ошибки конфигурации, scraper и конфликт выводятся
как HTML; конфликт остаётся HTTP 409.

## Проверка и результат

До реализации должны быть добавлены тесты:

1. `/sources` отображает сохранённый источник, статус и форму запуска;
2. успешный `POST /sources/:id/run` создаёт run, сохраняет вакансию и отвечает
   `303` с dashboard-фильтром источника;
3. запущенный источник отвечает `409` и не получает второй run.

Результат:

1. `/sources` отображает сохранённый источник, его status и форму запуска;
   пройдено.
2. Успешный `POST /sources/:id/run` сохраняет результаты и отвечает `303` на
   `/?source_id=<id>`; пройдено.
3. Уже running источник отвечает HTML-страницей с `409` и не получает второй
   run; пройдено.

Выполнены успешно: `go test ./...`, `go vet ./...`, `go build ./...` и
`git diff --check`.
