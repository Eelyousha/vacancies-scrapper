# Смена пользовательского статуса вакансии на dashboard

**Дата:** 2026-09-12
**Статус:** выполнено
**Этап ТЗ:** [этап 4](../05-implementation-plan.md)

## Проблема и цель

Dashboard показывает `user_status` вакансии, но пользователь не может сменить
его без прямого вызова JSON API. Это не завершает основной браузерный сценарий
работы с лентой.

Цель — дать в каждой карточке вакансии формы для переключения между `new`,
`viewed` и `hidden`, сохраняя активные фильтры dashboard после действия.

## Границы

Входит: POST-обработчик HTML, проверка допустимого статуса, переиспользование
репозитория обновления вакансии, действия в шаблоне, HTTP-тесты.

Не входит: массовые действия, undo, история изменений в HTML, изменение
`listing_status`, JavaScript и новый JSON-контракт.

## План и решение

Тесты зафиксировали: карточка содержит кнопки только для отличных
от текущего статусов; POST меняет значение в SQLite и redirect сохраняет query
параметры фильтра. Обработчик принимает ID из маршрута и status из формы,
использует существующий допустимый набор и возвращает `422` для неверного
значения. Для сохранения фильтров форма передаёт исходную query-строку скрытым
полем, а handler строит только относительный redirect на dashboard.

## Проверка и результат

Пройдены template- и HTTP lifecycle-сценарии: для `viewed` показаны только
действия `new` и `hidden`; корректное действие записывается и возвращает `303`
к фильтрованной ленте; неверное значение даёт `422` без изменения данных.
Выполнены: `go test ./...`, `go vet ./...`, `go build ./...`,
`git diff --check`.
