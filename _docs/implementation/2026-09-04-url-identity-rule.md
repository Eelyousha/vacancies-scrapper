# Правило идентичности вакансии по URL

**Дата:** 2026-09-04  
**Статус:** выполнено  
**Этап ТЗ:** [модель данных](../02-data-model.md)

## Решение

Изменение канонического URL означает новую вакансию. Вакансии не сопоставляются
по названию, компании или описанию: эти поля недостаточно устойчивы и могут
привести к ложному объединению разных объявлений.

Чтобы обычные технические различия ссылки не создавали новую вакансию,
канонизация удаляет fragment, `utm_*`, `gclid`, `fbclid`, приводит схему и хост
к нижнему регистру и стабилизирует порядок query-параметров.

## Ограничение и следующий шаг

Если конкретный сайт выпускает новый URL одной вакансии на каждом запуске,
нужно использовать YAML `identity.fallback_fields`. Его реализация добавлена в
backlog до архивации: без неё такой источник будет создавать ложные новые
вакансии и архивирование станет небезопасным.

## Проверка

Существующий тест подтверждает, что ссылки, различающиеся только tracking-
параметрами, фрагментом и порядком query, дают одну вакансию. Дополнительные
автоматические тесты для правила не требуются: это уточнение предметного
контракта, а не новая ветка кода.
