# API вакансий, источников и запусков

**Дата:** 2026-09-06
**Статус:** выполнено
**Этап ТЗ:** [этап 4 — интерфейс и источники](../05-implementation-plan.md)

## Проблема и цель

API пока позволяет проверить конфигурацию и запустить источник, но не отдаёт
данные, на которых строятся лента и сводка запусков. Нет безопасного метода
изменить пользовательский статус вакансии или экспортировать YAML.

Цель — закрыть JSON backend-контракт ТЗ для будущего локального UI.

## Границы

Входит:

* выборка вакансий с фильтрами, поиском, сортировкой и пагинацией;
* смена `user_status`;
* список источников, YAML export и import как неперсистентная передача YAML в dry run;
* latest runs и выборка полного состава запуска через `run_id`;
* HTTP- и репозиторные тесты.

Не входит:

* HTML/HTMX-интерфейс;
* расписания и фоновые задачи;
* редактирование истории вакансий.

## План и решение

`GET /api/vacancies` использует ограниченный набор фильтров из ТЗ и отдаёт
`items`, `total`, `limit`, `offset`. `PATCH /api/vacancies/:id` принимает
`user_status`. `GET /api/sources` и export читают только сохранённые источники.
Import не сохраняет YAML: возвращает его для обязательного `test-config`.
`GET /api/runs/latest` возвращает последние запуски; `run_id` в вакансии
ограничивает результат составом выбранного запуска.

## Проверка и результат

Проверены сценарии:

1. фильтры, поиск и смена user status возвращают ожидаемый набор — пройден;
2. PATCH принимает только допустимый user status — пройден;
3. список/export/import источников не сохраняет YAML — реализовано;
4. run_id ограничивает выборку составом выбранного запуска — реализовано;
5. latest runs отсортированы по времени начала — реализовано.

Выполнены `go test ./...`, `go vet ./...`, `go build ./...` и `git diff
--check` — успешно.
