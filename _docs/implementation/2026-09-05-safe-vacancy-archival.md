# Безопасная архивация вакансий

**Дата:** 2026-09-05
**Статус:** выполнено
**Этап ТЗ:** [этап 3 — дельта и архивирование](../05-implementation-plan.md)

## Проблема и цель

После завершения сбора вакансии, исчезнувшие из выдачи, остаются активными.
Архивировать их при неполном или ошибочном запуске опасно: отсутствие могло
быть вызвано лимитом, ошибкой страницы или отменой.

Цель — архивировать только активные вакансии источника, не замеченные в полном
успешном запуске, и отразить это в счётчике и составе запуска.

## Границы

Входит:

* архивирование в транзакции завершения `success`/`complete` запуска;
* `archived_at`, `archived_count` и disposition `archived`;
* тесты полного, частичного и ошибочного запуска.

Не входит:

* восстановление архивной вакансии при повторном появлении;
* пользовательское скрытие вакансии;
* изменение YAML или стратегии идентичности.

## План и решение

Архивация выполняется внутри `CompleteRun`, а не отдельным вызовом. Это
гарантирует, что статус и completion проверяются в той же транзакции, где
изменяется список вакансий. При `success` + `complete` выбираются только
`active` вакансии того же источника с `last_run_id`, отличным от текущего;
для каждой добавляется строка состава запуска `archived`.

## Проверка и результат

Проверены сценарии:

1. полный второй запуск архивирует невстреченную активную вакансию — пройден;
2. `partial`/`incomplete` не меняет статус невстретившейся вакансии — пройден;
3. `failed`/`unknown` не меняет статус невстретившейся вакансии — пройден;
4. archived count и disposition принадлежат завершившему запуску — пройден.

Выполнены `go test ./...`, `go vet ./...`, `go build ./...` и `git diff
--check` — успешно.
