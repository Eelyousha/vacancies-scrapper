# Обзор и архитектурные границы

## Цель

Локальное приложение собирает вакансии с сайтов прямых работодателей, хранит их актуальное состояние и историю ключевых изменений. Пользователь добавляет сайт через YAML-конфигурацию, сначала проверяет её в dry run, затем запускает сбор вручную. Запуски по расписанию — следующий этап проекта.

Данные и конфигурации хранятся в SQLite. Рабочий запуск не требует Node.js, NPM, Vite или внешнего клиентского фреймворка. Все статические ресурсы поставляются с приложением; CDN не используется.

## Реализовано в текущем MVP

* Проверка YAML и ручной запуск одного или нескольких источников.
* Извлечение вакансий с динамической пагинацией.
* Дедупликация, история отслеживаемых полей, безопасная архивация.
* Локальный интерфейс для ленты, запусков и конфигураций.
* Запрет пересекающихся ручных запусков одного источника, восстановление прерванных запусков и локальный журнал.
* Короткие повторные обходы с периодическим полным reconciliation для источников с пагинацией.

## Не реализовано в текущем MVP

* Обход защит, CAPTCHA и автоматическая классификация блокировок.
* Сравнение описаний и снимки всех блоков вакансии.
* Автогенерация YAML или обязательный пример конфига конкретного сайта.
* Аутентификация и удалённое развёртывание.
* Исполнитель cron/interval, фоновые jobs, лимиты параллельных браузеров и site-specific cursor/offset.

Ошибки браузера, признаки блокировки и прочие диагностические данные сохраняются для последующего анализа, но пока не обрабатываются автоматически.

## Технологии

* Go standard library (`net/http`) и встроенные HTML templates.
* `chromedp` для браузера и динамических страниц; `goquery` для итогового HTML.
* SQLite с миграциями.
* Локальный CSS без CDN и клиентского фреймворка.
