# YAML-конфигурация и сбор

## Контракт YAML

Конфигурация декларативна и описывает один источник. В БД сохраняется только YAML, успешно прошедший dry run. Сервер выдаёт краткоживущий `test_token`, привязанный к хешу YAML и тестовому URL; сохранение или обновление источника требует этот токен. Импорт YAML также должен пройти dry run.

Полный шаблон находится в [examples/source.example.yaml](examples/source.example.yaml). Его поля и допустимые значения образуют контракт конфигурации; новые поля нельзя добавлять без изменения парсера и документации.

`scroll_or_button` скроллит страницу и, когда доступна кнопка, нажимает её. Если пагинация не требуется, блок отсутствует: типа `none` нет. Динамика описывается ограниченными параметрами ожидания и остановки, а не произвольным JavaScript. Перед запуском валидируются обязательные поля, URL, допустимые значения, CSS-селекторы и лимиты.

Для подготовки нового конфига по HTML используется готовый [промпт для LLM](examples/llm-config-prompt.md). Полученный YAML обязательно проверяется через dry run: ответ модели — гипотеза, а не подтверждение работоспособности.

## Алгоритм запуска

1. Создать `scraping_runs` со статусом `running`, захватить блокировку источника и создать контекст с таймаутом.
2. Открыть изолированный Chromium, загрузить URL, дождаться `wait_for_selector`; при необходимости выполнить UI-поиск.
3. Выполнять пагинацию до стоп-условия, лимита, таймаута либо отмены и записывать диагностику.
4. Получить итоговый DOM, извлечь карточки goquery, очистить текст и нормализовать ссылки.
5. В одной транзакции создать/обновить вакансии, записать историю отслеживаемых полей и состав запуска.
6. Архивировать отсутствующие вакансии только при `status=success` и `completion_status=complete`.
7. Записать итоговые счётчики и состояние источника, снять блокировку.

При ошибке, блокировке, неполной выдаче или неопределённом завершении активные вакансии не архивируются. Глобальная конфигурация приложения задаёт лимит браузеров, таймауты, задержки и максимум карточек за запуск.
