Следующая задача — интерактивная лента вакансий: смена пользовательского
статуса и выбор состава конкретного запуска. Этап 3 завершён: идентичность
вакансий определена и отсутствующие результаты меняют статус только после
полного успешного запуска.

## Этап 0 — фундамент

**Цель:** воспроизводимая разработка и безопасная схема данных.

* Go-модуль, конфигурация, миграции, SQLite-репозиторий, локальные статические ресурсы.
* Тесты миграций и внешних ключей.

**Критерий успеха:** чистая БД поднимается одной командой, миграции идемпотентны, интерфейс не требует Node.js или CDN.

Детальные решения по завершённым инкрементам ведутся отдельно в
[журнале реализации](implementation/README.md). Первый инкремент этапа 0 —
[SQLite-схема](implementation/2026-09-01-sqlite-schema.md).

## Этап 1 — конфигурация и детерминированный парсинг

**Цель:** проверять YAML и селекторы до браузера.

* YAML-структуры, валидация, нормализация ссылок, goquery-парсер.
* HTML-фикстуры и unit-тесты для пустых карточек, относительных URL и fallback-фингерпринта.

**Критерий успеха:** неверный конфиг объясняет ошибку, а парсер стабильно извлекает ожидаемые данные из фикстур.

## Этап 2 — ручной сбор

**Цель:** замкнуть сценарий «dry run → сохранение → запуск».

* Chromedp, ожидания, UI-поиск, `scroll_or_button`, таймауты, `test_token`.
* Ручной API-запуск и журнал результатов.

**Критерий успеха:** dry run показывает 3–5 карточек; сохранённый источник запускается и не зависает на бесконечной подгрузке.

## Этап 3 — дельта и архивирование

**Цель:** корректно различать новые, изменённые, неизменившиеся и исчезнувшие вакансии.

* Транзакционное обновление, история, состав запуска, пользовательские статусы.
* Архивация только после полного успешного запуска.

**Критерий успеха:** неизменный повторный запуск даёт `unchanged`, изменение зарплаты сохраняет историю, неудачный запуск не архивирует вакансии.

## Этап 4 — интерфейс и источники

**Цель:** все сценарии доступны без прямой работы с API.

* Лента, фильтры, сводка, конструктор и импорт/экспорт.

**Критерий успеха:** пользователь выполняет этапы 1–3 полностью из локального браузера.

## Этап 5 — автоматизация и надёжность

**Цель:** безопасные запуски нескольких источников по расписанию.

* Cron/interval, таймзоны, запрет пересечений, лимиты браузеров, диагностика.
* Интеграционные тесты расписания, отмены и параллельных запусков.

**Критерий успеха:** нет дублей запусков, смена системной таймзоны требует явного выбора, ошибка одного источника не останавливает остальные.
