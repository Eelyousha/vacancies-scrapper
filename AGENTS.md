# Правила работы в проекте

Для задач разработки используйте репозиторный skill
[`project-development-workflow`](.codex/skills/project-development-workflow/SKILL.md):
он маршрутизирует к нужным разделам ТЗ, журналу и backlog. Этот файл остаётся
источником обязательных правил.

## Обязательный порядок для каждого инкремента

1. **План в документации.** До изменения кода создать запись по
   [_docs/templates/implementation-record.md](_docs/templates/implementation-record.md)
   в `_docs/implementation/`. Указать цель, границы, связь с ТЗ и критерий
   готовности. Поставить статус `запланировано`.
2. **Тесты.** До реализации добавить или обновить тесты для поведения, которое
   можно проверить изолированно. Если тесты неприменимы, явно объяснить причину
   в записи инкремента.
3. **Реализация.** Написать минимальный код в границах плана. Комментировать
   нетривиальные решения, инварианты, транзакции и причины выбора, но не
   дублировать очевидный код.
4. **Сверка с ТЗ.** После реализации проверить соответствие
   `_docs/01-overview.md`–`_docs/05-implementation-plan.md`. Обновить запись
   инкремента: фактический результат, проверки, ограничения, отклонения и
   следующий шаг. Если ТЗ неполно или противоречиво, остановиться и запросить
   уточнение до расширения границ задачи.

## Документация и backlog

* В `_docs/implementation/` хранятся датированные записи завершённых и текущих
  инкрементов. Запись после статуса `выполнено` не переписывается ради новой
  работы: создаётся следующая запись со ссылкой на предыдущую.
* Идеи и порядок будущей работы ведутся в [_docs/backlog.md](_docs/backlog.md).
  При начале работы задача меняет статус на `в работе` и получает ссылку на
  запись инкремента; после проверки — на `выполнено`.
* Перед началом работы сверять задачу с backlog и ТЗ. Backlog помогает выбрать
  порядок, но не заменяет ТЗ.

## Проверки

После изменения Go-кода выполнить `go test ./...`, `go vet ./...`, `go build
./...` и `git diff --check`. Для документационных изменений достаточно
проверить ссылки, Markdown-разметку и `git diff --check`.

Не изменять посторонние пользовательские файлы и незакоммиченные изменения.
